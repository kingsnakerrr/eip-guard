# 判定规则说明（为什么"22 端口能连通"不能说明问题）

## 一、先说你提的两种可疑情况

> 有可能 22 端口可以连接使用 SSH 但是节点连不上
> 也有可能 SSH 和节点全部坏了端口都给封了

这两种情况，**靠"22 通不通"都判断不出来**。原因：

| 观察到的现象 | 可能的真实原因 | 说明什么 |
|---|---|---|
| 22 通、443 不通 | ① 443 服务挂了 ② 只封了 443 | 说不清，要看 443 在墙外通不通 |
| 22 也不通、443 不通 | ① 22 和 443 都被封 ② SSH 和 Web 都挂了 | 说不清，要看墙外 |

**关键点**：22 端口的结果和 443 端口的结果是两件独立的事。用 22 去推断 443 是否被墙，逻辑上不成立。

- 上一版用"22 能连"来证明"IP 没被封"——错。22 能连只证明 22 的服务活着。
- 反过来"22 连不上"也不能证明 IP 被封——可能是 sshd 没跑、安全组没放 22、或者 22 端口本身被单独封了。

## 二、正确判据：同一端口，国内外对比

这就是 ping.pe 的做法，也是本项目现在的做法：

```
对业务端口 443：
    国内探针连 443  ──┬── 不通 ──┐
                      │          ├── 国外通  → 443 被墙
                      │          └── 国外也不通 → 443 服务/防火墙问题
                      └── 通 ────────→ 正常（再看 TLS/HTTP）
```

只看一个方向永远得不出结论。**"国内不通 + 国外通" 是判定被墙的充分条件**，这是唯一可靠的定义。

## 三、完整判定表

| 业务端口 国内 | 业务端口 国外 | 其它端口 国内 | 结论 | 该做什么 | 自动换 IP |
|---|---|---|---|---|---|
| ✗ | ✓ | 都不通 | **IP 被墙** | 换 IP | ✅ |
| ✗ | ✓ | 有能通的 | **端口被墙** | 换端口（换 IP 也可能有用） | ❌ |
| ✗ | ✗ | — | **服务不可用** | 查进程/安全组/防火墙 | ❌ |
| ✓ | — | — | 正常（再看 TLS） | — | ❌ |
| ✓(TLS ✗) | ✓(TLS ✓) | — | **TLS 被阻断** | 换域名/协议 | ❌ |
| ✓(HTTP ✗) | ✓(HTTP ✓) | — | **数据面被阻断** | 换协议/混淆 | ❌ |
| 缺国内或国外探针 | | | **无法判定** | 补探针 | ❌ |

### 关于"其它端口"的作用

这是区分第一行和第二行的关键：

- `443` 国内不通，`22` 国内能连 → **换 IP 没用**，因为这说明这台 IP 本身在国内是可达的，只是 443 这个端口被针对了。换 IP 后新 IP 的 443 大概率也会被封。
- `443` 和 `22` 国内都不通 → 整台 IP 有问题 → 换 IP 有效。

所以你需要在 `aux_ports` 里填这台机器上**真实开放的其它端口**。

### 你举的两种情况的最终结论

**情况 1：22 通、443 不通**
- 若 443 国外通 → **端口被墙**。换端口最有效（比如 443→8443），换 IP 也可能有用但更贵。
- 若 443 国外也不通 → **服务不可用**，443 服务挂了，换 IP 完全没用。

**情况 2：22 和 443 都不通**
- 若两个端口国外都通 → **IP 被墙**，换 IP 有效。
- 若国外也不通 → **服务不可用**（或安全组/防火墙），换 IP 没用。

注意：判断的依据始终是**业务端口本身在国外的表现**，而不是"22 通不通"。

## 四、ping.pe 的作用

本项目在每条告警里都附上 ping.pe 的自查链接：

```
🔗 自查：https://ping.pe/1.2.3.4:443?host=hk.example.com
```

点开就能看到全世界的检测结果，和程序自动跑的是同一套逻辑，可以人工复核。程序只是把这件事自动化了，并且加了：

- 定时轮询（不用你手动去点）
- 连续 N 次才动作（防抖）
- 自动换 IP + 改 CF 解析 + 验证 + 回滚

## 五、探针怎么部署

至少两台，一台在国内、一台在国外：

```bash
# 国外 VPS
sudo ./install.sh --probe --zone overseas

# 国内 VPS（或你在国内的机器）
sudo ./install.sh --probe --zone cn
```

两台用**同一个 token**，然后填进主程序的 `.env`：

```
PROBE_CN_URL=http://国内探针IP:8787
PROBE_OS_URL=http://国外探针IP:8787
PROBE_AGENT_TOKEN=同一个token
```

没有国内探针时，程序会明确报 `无法判定`，**不会瞎换 IP**。也可以用 `provider: checkhost` 走免费公共检测网（其节点里常有中国的），但会限流、节点不固定。
