# 国内探针在家宽后面怎么办

**结论先说：家宽不需要公网 IP。** 用「反向探针」，让家里那台主动连主程序。

---

## 为什么不需要公网 IP

之前的设计是「主程序去问探针」，所以探针必须能被外面访问，家宽就得有公网 IP。
现在的反向模式反过来：

```
    家宽机器（无公网 IP）                    国外 VPS（主程序）
    ┌──────────────────┐                    ┌──────────────────┐
    │ client.py        │ ──主动连 8790────→ │ hub (WebSocket)  │
    │ 收到任务后本机探测 │ ←──下发任务─────── │ 判定 + 换 IP     │
    │ 结果回传          │ ──回传结果────────→ │ 通知 Telegram    │
    └──────────────────┘                    └──────────────────┘
```

家宽那台**出站连接**就行（家宽出站从来不受限），完全不需要：
- 公网 IP
- 端口转发
- 路由器动任何设置

---

## 装法

### 主程序侧（国外 VPS）

`config.yaml` 里开启 hub：

```yaml
detect:
  provider: "hub"          # 或者保留 probe_agent，只要 enabled: true 也会走 hub
  hub:
    enabled: true
    port: 8790
    token: "${PROBE_AGENT_TOKEN:-}"
```

安全组放行 **8790**。

### 家宽侧（PVE 里的 Debian）

```bash
bash <(curl -Ls https://raw.githubusercontent.com/kingsnakerrr/eip-guard/main/install.sh) \
  --probe --mode client --zone cn \
  --hub ws://国外VPS的IP:8790 \
  --token 你的PROBE_AGENT_TOKEN
```

装完它会自动连上去，不用做别的。日志：

```bash
journalctl -u eip-probe-client -f
# 连接主程序 ws://1.2.3.4:8790/agent …
# 已连接，zone=cn name=debian12-backup，等待任务
# 任务 abc123: 47.243.1.25 [443, 22]
```

### 主程序侧确认

```bash
# 看 hub 上有哪些探针在线
curl -s http://127.0.0.1:8790/hub/status
# {"ok": true, "agents": [{"name": "debian12-backup", "zone": "cn", "tasks": 3}]}

# 或者直接跑一轮探测
cd /opt/eipguard
.venv/bin/python -m eipguard -c config.yaml --once
```

## 混合模式

两种模式可以同时用，各自负责一侧：

```yaml
detect:
  provider: "probe_agent"
  hub:
    enabled: true          # 家里那台走反向
    port: 8790
    token: "${PROBE_AGENT_TOKEN:-}"
  probe_agent:
    agents:
      - url: "http://国外VPS的IP:8787"     # 同机直连探针
        token: "${PROBE_AGENT_TOKEN}"
        zone: "overseas"
        name: "os-local"
```

`provider: probe_agent` + `hub.enabled: true` 时，程序会优先用 hub 里对应 zone 的探针，没有就用直连地址。

## 常见问题

### 服务在跑但主程序说「没有在线探针」

1. 看家宽那台的日志：`journalctl -u eip-probe-client -f`
   - `连接主程序 …` 一直重试 → 主程序 8790 没放行，或 IP 填错
   - `已连接` 但主程序看不到 → token 不一致
2. 主程序侧确认端口在听：`ss -lntp | grep 8790`
3. 确认 `config.yaml` 里 `hub.enabled: true`

### token 不一致

两台都要用同一个：

```bash
# 主程序
grep PROBE_AGENT_TOKEN /opt/eipguard/.env
# 家宽
grep PROBE_TOKEN /opt/eip-probe/agent.env
```

### 断线了会怎样

`client.py` 会自动重连，退避从 2 秒逐步增加到最多 60 秒。主程序侧期间会报「无法判定」但**不会乱换 IP**。

### 家里断电/重启后

systemd 服务已 `enable`，开机自启，会自动重新连上。

## 和「普通探针」怎么选

| 机器 | 用哪种 |
|---|---|
| 家宽 / NAT / PVE 内网 | **反向（`--mode client`）** |
| 有公网 IP 的 VPS | 普通（默认，`--probe --zone xxx`） |
| 主程序和探针同一台 | 普通，填 `http://127.0.0.1:8787` |

判定逻辑完全一样（都是「同一端口国内不通 + 国外通」），只是连接方向不同。

---

## 如果你就是想用普通模式

那才需要公网 IP + 端口转发，或者用 Tailscale / frp 打通。这三个方案仍然保留，见 git 历史里的旧版本文档，或者直接：

- **Tailscale**：两边装，用 100.x.x.x 地址互访
- **frp**：家里主动连 VPS，反向暴露 8787
- **CF Tunnel**：家里跑 cloudflared 映射到域名

但**反向模式比它们都简单**，不需要额外软件，所以优先推荐它。
