# 国内探针在家宽后面怎么办

主程序装在国外 VPS，需要访问你家里 PVE 里那台国内探针。
**家宽最常见的两个问题：没有公网 IP、有公网 IP 但 80/443 被封。**

先自测，一条命令：

```bash
# 在国外的机器上执行
bash <(curl -Ls https://raw.githubusercontent.com/kingsnakerrr/eip-guard/main/install.sh) \
  --check-probe http://你的家宽地址:8787 --token 你的token
```

三种结果对应三种方案：

| 结果 | 说明 | 用哪个方案 |
|---|---|---|
| TCP 可达 + 探测成功 | 能直接访问 | 方案 0（已通） |
| TCP 不可达 | 家宽没公网 IP，或端口没放行 | 方案 1（Tailscale，推荐） |
| 能连但探测请求超时 | 端口通但服务不对 | 检查 token / 端口占用 |

---

## 方案 0：已经通了

直接在主程序向导里填：

```
国内探针地址：http://你的公网IP:8787
国外探针地址：http://国外IP:8787
探针 token：两台一致的那个
```

前提（三个都要满足）：

1. 家宽有**公网 IPv4**（不是运营商 NAT 的 100.64.x.x）。在 PVE 的 Debian 上查：
   ```bash
   curl -s https://api.ipify.org     # 公网出口 IP
   ip -4 addr show | grep inet       # 本机 IP
   ```
   两个一样 → 有公网 IP；本机是 192.168.x.x 但公网是别的 → 在路由器后面。
2. 路由器上做了**端口转发**：外网 8787 → Debian 的内网 IP:8787。
3. 云防火墙/路由器没有拦 8787。

有公网 IPv4 的家宽越来越少，而且即使有，8787 暴露在公网也有被扫到的风险，建议加个来源限制（只允许国外 VPS 的 IP）。

---

## 方案 1：Tailscale（最推荐，5 分钟，免费）

不管有没有公网 IP 都能用，而且不用在路由器上开端口，安全性更好。

家里那台和国外 VPS 加入同一个 Tailscale 网络，互相用 100.x.x.x 内网地址通信。Tailscale 会打洞直连，打不通时走中继，通常速度够探测用。

### 1.1 两边都装

```bash
# 家里那台（PVE 里的 Debian）
curl -fsSL https://tailscale.com/install.sh | sh
tailscale up          # 打印一个链接，浏览器打开登录

# 国外 VPS
curl -fsSL https://tailscale.com/install.sh | sh
tailscale up          # 用**同一个账号**登录
```

### 1.2 拿到家里的 Tailscale IP

```bash
# 家里那台
tailscale ip -4
# 输出类似 100.101.102.103
```

### 1.3 国外 VPS 上验证

```bash
tailscale status                       # 应该能看到家里那台 online
curl -s http://100.101.102.103:8787/health
# {"ok": true, "zone": "cn", ...}
```

通了就填进主程序：

```
国内探针地址：http://100.101.102.103:8787
```

### 1.4 注意

- 探针默认监听 `0.0.0.0`，Tailscale 网卡也能访问，不用改配置。
- 想更严一点，让探针只监听 Tailscale 网卡：
  ```bash
  # /opt/eip-probe/probe.env 加一行（探针支持 --host）
  # 或直接改 systemd：
  systemctl edit eip-probe
  # [Service]
  # ExecStart=
  # ExecStart=/usr/bin/python3 /opt/eip-probe/server.py --port 8787 --host 100.101.102.103
  ```
- 国内访问 Tailscale 登录页可能需要代理；装完登录过一次后长期不用再登。

## 方案 2：frp / rathole 内网穿透（国内可用性好）

如果 Tailscale 在国内连不上（部分地区登录困难），用 frp：家里主动连国外 VPS，把 8787 反向映射过去。

### 2.1 国外 VPS 跑 frps（服务端）

```bash
# 下载
curl -LO https://github.com/fatedier/frp/releases/download/v0.61.1/frp_0.61.1_linux_amd64.tar.gz
tar xzf frp_0.61.1_linux_amd64.tar.gz && cd frp_0.61.1_linux_amd64

# frps.toml
cat > frps.toml <<'EOF'
bindPort = 7000
auth.method = "token"
auth.token = "换成一个长随机串"
EOF

nohup ./frps -c frps.toml > frps.log 2>&1 &
```

记住 VPS 公网 IP、7000 端口、token。

### 2.2 家里跑 frpc（客户端）

```bash
# 同样下载解压
# frpc.toml
cat > frpc.toml <<'EOF'
serverAddr = "国外VPS的IP"
serverPort = 7000
auth.method = "token"
auth.token = "和上面一致"

[[proxies]]
name = "eip-probe"
type = "tcp"
localIP = "127.0.0.1"
localPort = 8787
remotePort = 8787
EOF

nohup ./frpc -c frpc.toml > frpc.log 2>&1 &
```

### 2.3 主程序里填

```
国内探针地址：http://127.0.0.1:8787     ← 因为主程序就在国外这台，frps 在本机
```

**注意**：这样填 `127.0.0.1` 时，主程序认为"探针在本机"，但实际代表的是国内视角——这是对的，`zone` 由探针自己上报（`ZONE=cn`），不是由地址决定。

### 2.4 记得放行

国外 VPS 安全组放行 7000（frp 控制端口）和 8787（可选，如果用回环就不用）。

## 方案 3：Cloudflare Tunnel（家里能出网即可）

家里跑 `cloudflared`，把 8787 映射到一个域名。好处是只要家里能上网就行，不用公网 IP。

```bash
# 家里那台
curl -L https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -o /usr/local/bin/cloudflared
chmod +x /usr/local/bin/cloudflared
cloudflared tunnel login
cloudflared tunnel create eip-probe
cloudflared tunnel route dns eip-probe probe.example.com
cloudflared tunnel run --url http://127.0.0.1:8787 eip-probe
```

然后主程序填 `https://probe.example.com`。

**缺点**：CF 会代理 HTTP 请求，延迟偏高；探测结果本身不受影响（探针是在家里发起的连接），但主程序调接口会慢一点。另外 CF 免费版限制请求体大小，探针请求很小，没问题。

## 方案对比

| 方案 | 需要公网 IP | 需要开放端口 | 国内可用性 | 难度 |
|---|---|---|---|---|
| 0 端口转发 | ✅ 必须 | ✅ 8787 | 好 | 简单，但多数家宽没有公网 IP |
| 1 Tailscale | ❌ | ❌ | 部分地区需代理登录 | **最简单** |
| 2 frp | ❌ | 7000 | **最好** | 中等 |
| 3 CF Tunnel | ❌ | ❌ | 好 | 中等，延迟略高 |

**推荐顺序：Tailscale → frp → 端口转发**。

## 一个更省事的思路

如果你有**国内 VPS**（阿里云/腾讯云的国内地域，几块钱一个月），直接把国内探针装在那上面，就完全没有家宽问题：

```bash
# 国内 VPS 上
bash <(curl -Ls .../install.sh) --probe --zone cn --token xxx
```

它有公网 IP、端口可控、稳定性比家宽好，也不会因为家里断网导致探针离线。

**会不会影响判定准确性？** 不会。判定只看"这个 IP 端口从国内能不能连上"，国内 IDC 和家宽都是国内网络，结论一致。除非你的业务只对某些家宽运营商有影响，那才需要特定线路的探针。

## 排查清单

主程序报「无法判定：没有国内探针」时：

1. 国外机器上执行 `--check-probe`，看具体卡在哪一步
2. `curl -s http://探针地址/health` 有没有返回
3. 家里那台 `systemctl status eip-probe` 是否 active
4. 家里那台 `ss -lntp | grep 8787` 是否在监听
5. 两台的 `PROBE_AGENT_TOKEN` 是否一致（`cat /opt/eip-probe/probe.env`）
6. 家里那台的 `ZONE` 是否是 `cn`（`cat /opt/eip-probe/probe.env`）
